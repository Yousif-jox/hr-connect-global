# docs — Meridian HR website requirements

مجلد مستندات المتطلبات للموقع. المستند مُولَّد آلياً من ملف بيانات المتطلبات ومن ملف بيانات الوظائف
الموجود في `src/data/jobs.ts`، وبالتالي لا يمكن أن يخالف الكود.

## المحتوى

| الملف | الوصف |
|---|---|
| `Meridian-HR-Website-SRS.docx` | مستند المتطلبات الكامل (٢٣ صفحة، ٥٧ متطلب وظيفي + ٢٢ غير وظيفي) — قابل للتعديل |
| `Meridian-HR-Website-SRS.pdf` | نفس المستند بصيغة PDF للعرض السريع والمشاركة |
| `srs-data.json` | ملف بيانات المتطلبات (بنية الموقع، رموز الهوية، المتطلبات، المخاطر، الأسئلة المفتوحة) |
| `build-srs.mjs` | سكربت توليد المستند من الملفين أعلاه |
| `check-jobs-data.mjs` | سكربت فحص بيانات الوظائف: تطابق اللغتين، تفرّد المعرّفات، عدم وجود حقول فارغة |

## إعادة التوليد

بعد أي تعديل على `srs-data.json` أو على `src/data/jobs.ts`:

```sh
npm i -D docx
node --experimental-strip-types docs/build-srs.mjs
```

لفحص بيانات الوظائف فقط:

```sh
node --experimental-strip-types docs/check-jobs-data.mjs
```

يجب أن ينتهي الفحص بـ `PROBLEMS: NONE`.

## ملاحظة

المستند يعرض أرقاماً محسوبة من البيانات نفسها (عدد الوظائف، عدد بنود المتطلبات، إجماليات المتطلبات)،
فإذا أضفت وظيفة أو متطلباً في الملفات المصدرية يتغيّر الرقم في المستند تلقائياً عند إعادة التوليد.

# الموقع: الصفحات ونموذج التقديم

## الصفحات

| المسار | الوصف |
|---|---|
| `/` | الصفحة التعريفية بأقسامها |
| `/jobs` | الوظائف المتوفرة (٢٤ بطاقة) |
| `/jobs/<id>` | صفحة مستقلة لكل وظيفة + نموذج التقديم (٢٤ صفحة) |
| `/requirements` | شروط التوظيف |
| `/about` | عن الشركة |

| `/privacy` | سياسة الخصوصية |
| `/terms` | شروط الاستخدام |
| `/sitemap.xml` | خريطة موقع تُولَّد آلياً من بيانات الوظائف |

## تشغيل نموذج التقديم

النموذج يعمل من أول لحظة بشكلين:

1. **بدون أي إعداد** — يتحوّل تلقائياً إلى فتح البريد برسالة جاهزة تحتوي ما أدخله المتقدم.
2. **بالإرسال المباشر** — يُفعَّل بإضافة متغيرات البيئة التالية، دون أي تعديل في الكود:

```sh
RESEND_API_KEY=...            # مفتاح خدمة إرسال البريد (Resend)
APPLY_TO_EMAIL=careers@your-domain.com    # صندوق استقبال الطلبات
APPLY_FROM_EMAIL="Meridian HR Careers <careers@your-domain.com>"   # مرسل موثّق على النطاق
```

مسار الخادم `/api/apply` يتحقق من الحقول بـ zod، ويقبل السيرة الذاتية بصيغ PDF/DOC/DOCX
بحد أقصى ٥ ميجابايت، ويحتوي على حقل فخ مخفي وتحديد لمعدل الطلبات لكل عنوان شبكة.

## قراءة السيرة الذاتية

عند إرسال الطلب تُقرأ السيرة الذاتية على الخادم ويُستخرج نصها الكامل، ليُضمَّن في بريد الإشعار
في قسم منسّق — فيقرأ فريق التوظيف المحتوى دون فتح المرفق، ويبقى الملف الأصلي مرفقاً كما هو.

| الحالة | ما يحدث |
|---|---|
| PDF | يُستخرج النص كاملاً (قد يتأثر ترتيب الترقيم العربي قليلاً في ملفات PDF) |
| DOCX | يُستخرج النص كاملاً بعناوينه وفواصله، والعربي سليم |
| `.doc` قديم | يُعلن كغير مدعوم في البريد دون إفشال الطلب |
| ملف تالف أو فارغ | يُعلن في البريد، والطلب يصل مع المرفق |

القراءة أقصاها ٢٠٬٠٠٠ حرف في البريد، ولا تمنع وصول أي طلب عند فشلها. الملفات المرتبطة:
`src/lib/cv-text.ts` (القارئ) و `src/lib/application-email.ts` (بناء البريد).

لفحص القارئ والبريد:

```sh
node --experimental-strip-types docs/check-cv-reader.mjs                  # يبني ملف اختبار داخلياً
node --experimental-strip-types docs/check-cv-reader.mjs path/to/cv.pdf   # ويختبر PDF حقيقي أيضاً
```

## ملاحظات تشغيلية

- الصفحات الافتراضية للغة إنجليزية ما لم يختر الزائر العربية؛ ويُحفظ الاختيار في المتصفح.
- نموذج التقديم لا يخزّن الطلبات في قاعدة بيانات: تُسلَّم بالبريد، لذلك لا يوجد سجل طلبات داخل الموقع.
- عنوان الوظيفة يُستخرج من بيانات الموقع نفسها لا من الطلب، فلا يمكن إدخال نص حر في إشعار التوظيف.
- السياسات المنشورة تحتاج مراجعة قانونية قبل الإطلاق العام (انظر الأسئلة المفتوحة في المستند).
